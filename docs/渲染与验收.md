# 本地工具与验收

## 配置和代码的职责

每期位于 `videos/<slug>/`，slug 为小写英文、数字与连字符。

| 文件 | 内容 |
|---|---|
| brief.md | 处境、锚词、主体、事件链和结尾答案 |
| research.md | 来源、事实和边界，年份人名数字引文清单 |
| storyboard.md | 具体动作、时间码、转场、字幕、音效和锚词位置 |
| visual-review.md | 全片分镜总览、动态分镜版本、视觉重复问题与返修复查记录 |
| film.json | 资源、入口、源码列表、检查时点、音效和制作状态 |
| plan.json | 标题、锚词、实际时长、帧数、首高潮帧号和字幕 |
| plan.js | 工具从 plan.json 同步的浏览器数据，不手工改 |
| narration.json | 中文旁白、声音、实测入窗限制、首高潮保护区与 constant 配乐模式 |
| audio/narration/ | 按语义段落cue缓存的原始 WAV、文本/音色/语速签名、可用的词边界和音频哈希；兼容旧逐句缓存 |
| scenes.js 或多个场景模块 | 对应本主题的可见事件和画面 |
| index.html | 固定 1920×1080 Canvas 与本地字体、脚本引用 |
| player.html | 本地音乐播放和逐帧滑动预览，不进入成片 |
| build/ | 当前工作输出、源帧预览、分段视频和验证记录 |
| reference/ | 历史已交付版本和参考核对，不当作新渲染结果 |

`plan.json` 最小字段如下；实际字幕须按片长扩展：

```json
{
  "title": "片名",
  "anchor": "锚词",
  "duration": 159.25,
  "fps": 30,
  "frames": 4778,
  "impact_frame": 511,
  "subtitles": [
    {"start": 0.1, "end": 4.0, "zh": "一句短字幕", "en": "One short line."}
  ]
}
```

帧号从 0 算，`frames=ceil(duration*30)`。字幕不得互相重叠或超出音乐时长。`load` 会检查这些条件并同步 plan.js。示例计划里旧的 visual/transition 字段仅为早期文字备注，当前具体动作以 storyboard.md 和 JS 源码为准。

`film.json` 中 `sources` 必须列全所有视觉源文件（包括 plan.js）；引入新 JS 或图像时也加入列表，使修改后旧预览和旧分段失效。字体会自动纳入源码签名。`music` 相对本期目录解析；本项目已打包的音乐用 `../../assets/music/...`。不要写原会话或桌面的绝对路径。

`preview_times` 是单帧检查；`motion_ranges` 是 `[开始秒, 结束秒, 英文名称]`，每段抽 8 帧形成动作序列；`review_times` 是从最终编码视频中提取的检查帧。

音效例子：`{"time":17.033333333333335,"kind":"impact","volume":0.17,"duration":0.65}`。支持 impact、scan、plate、hit、engine_loss、selection、wind、paper、close。这些是轻量程序音效，可依新主题换成有来源的本地音效并扩展混音器。

## 确定性画面接口

入口页面需提供：

```javascript
window.READY = true;             // 字体、素材已加载才置为 true
window.render = t => draw(t);    // 输入绝对秒数；同一 t 始终同一画面
window.audit = t => [/* 越界文本信息；无问题返回空数组 */];
```

画布必须是 `id="stage"`、1920×1080。场景自身不使用实时计时推进，不依赖上一帧累积，不用未固定种子的随机数。`requestAnimationFrame` 仅用于 player.html 播放器，根据音频当前时间调用 render；正式渲染逐帧输入 `frame/30`。

字体和素材全为本地文件。先等待字体和图片加载再声明 READY，加载失败要报错，不能静默回退字体。标题/字幕绘制时记录实际文字边界；特殊变换须将边界映射到画布坐标。

## 工具命令

以下命令在项目根目录执行：

```powershell
python .\vibe.py doctor
python .\vibe.py new sunk-cost --title '舍不得' --topic '沉没成本' --narrated
python .\vibe.py check sunk-cost
python .\vibe.py analyze-music sunk-cost
python .\vibe.py narrate sunk-cost --tts-cli $ttsCli
python .\vibe.py preview sunk-cost
python .\vibe.py preview sunk-cost --times '16.9,17.033333333333335,17.066666666666666'
python .\vibe.py render sunk-cost --start 0 --end 660 --name opening --jobs 2
python .\vibe.py mix sunk-cost
python .\vibe.py serve sunk-cost
```

`--narrated` 创建云健中文配音骨架和空白 narration.json，配乐固定增益从 −18dB 起步。先写本期正文，再按 README 准备 ttsCN 脚本及可选配音依赖，将 `$ttsCli` 设为本机安装位置。空 cues 会明确报错；不会生成占位配音。已有示例音频缓存可直接 mix，无须安装 TTS 依赖或联网；默认不带 --narrated 的 new 兼容无口播工具测试。

`--times` 在本期默认检查点之外追加抽帧。输出时量化到最近的 30fps 帧。短片段的 start/end 都是帧号，end 不含；0–660 帧即 22 秒，使用独立 name，避免覆盖完整 picture。

当前 CLI 的短片段 render 只输出无声画面；要试听开头可在 player.html 配合完整混音播放，或从完成的全片导出开头。不能把无声短片段当作完成音画卡点验证。

`analyze-music` 输出实际解码时长、30fps 建议帧数和 10ms RMS CSV。它不自动确定音乐重拍；选择落点后同步 plan、场景动作、字幕、SFX 与抽帧时点。改音源不能只改文件名。

完成内容、动作、分镜，以及下文“全片视觉重复与动态分镜复核”的编辑检查后，将 production_ready=true，再按顺序。该配置是制作状态声明，不会自动执行审片：

```powershell
python .\vibe.py preview sunk-cost
# 查看 build/review/*.png、overview_*.jpg 和 transition_*.jpg，修正后重新预览
python .\vibe.py render sunk-cost --jobs 4
python .\vibe.py finalize sunk-cost
```

渲染中断可用相同分段参数 `--resume`：

```powershell
python .\vibe.py render sunk-cost --jobs 4 --resume
```

只有源码签名与帧数相符的分段才复用。改变 jobs 会改变分段边界；不保证复用旧分段。渲染期间不要修改视觉源码。

## 输出与人工复核

下列 build 为默认输出目录，实际以 film.json.output 为准；phantom-jam使用build，较早的missing-planes配音示例使用build-voiceover-stable。`build/picture.mp4` 是完整无声画面；`build/narration.wav` 是统一处理后的旁白；`build/narration-timing.json` 是按cue实测的段落时间轴；`build/soundtrack.wav` 是旁白、音乐和音效混音；`build/final_video.mp4` 是成片。`finalize` 重建混音，检查完整渲染源与当前预览一致，封装音轨，再进行全片解码、规格、帧数、时长、真峰值、音轨互相关同步与编码后抽帧。

配音验收还要核对 actual_end 不超出窗口、无段落重叠、正常语速、字幕对应与保护区无旁白。检查实际可听段间空档，不能把cue窗口间距当作听感间隔；词级元数据和字幕对齐方法见配音流程。soundtrack.json 的 narration 应显示 music_mode=constant、music_duck_db=0、music_envelope_min=music_envelope_max=1。固定增益不代表音乐波形恒定，原曲强弱仍会保留；不能误把音乐原有渐强当作逐句闪避。

检查记录位于 `build/review/validation.json`、`final_probe.json`、`decode_and_audio.log`、`encoded_review.jpg`。near_total_black_intervals 仅报告近乎全黑持续区段，需判断是否有意设计；不能因整片是暗色就自动失败。

必须另写 `build/review/人工复核.md`，记录实际看过的图和动作序列、修正内容、高潮落点，以及试听范围。自动文字边界不能识别全部遮挡、对比或叙事问题；音轨互相关验证封装时序，不能自动证明动作“踩准了情绪”。

成片默认保存在本期 `build/final_video.mp4`。需要另外导出时，使用用户当次指定的目录和新版本名，校验源目标 SHA-256 一致，保留已交付版本。项目不预设用户的桌面、主目录或系统视频目录。不得直接拿 reference/ 下的旧视频当作新主题或新渲染的结果。

## 路径与其他电脑

仓库可放在任意目录；工具从脚本位置推导项目根目录，不依赖启动命令所在目录。源码、音乐、字体和配置使用相对路径；`film.json` 的资源路径相对本期目录，报告中的项目内路径相对仓库根目录。用户主动指定的项目外资源可使用其实际路径，该路径只对该次环境有效，不作为默认配置。

预览接触表使用仓库自带的 Lora 字体。浏览器由 Playwright 寻找本机 Chrome 或已安装的 Chromium，FFmpeg/FFprobe 从 PATH 寻找，不引用某台电脑的软件安装目录。Windows 和 macOS/Linux 的环境安装命令见 README；换电脑需重建虚拟环境。

## 连续动作、分段编码和交付复核

静帧之外必须查看动作序列：触发前、过程、结果保持，以及转场前中后。特别看停稳是否能辨认、主体驶出后问题是否仍可见、前后镜头是否丢失追踪对象、遮罩退出是否造成相机跳变。几何边界检查不能证明上述叙事关系成立。示意模型另做领域约束检查，不能只看画面漂亮。

并行渲染拼接时，MP4的容器时长可能经过毫秒舍入。当前 tools/render.py 在concat清单中显式写入每段“帧数÷FPS”的时长，保持分段接缝位于帧格上。验收不仅看名义r_frame_rate，也核对实际帧数、avg_frame_rate与接缝帧时间戳；否则片长接近正确仍可能有节奏漂移。

最终编码与交付压缩后的文件都要重查，不能仅复用源码预览。抽查开场、重拍前后、最密集说明、关键结论和片尾；必要时看原尺寸图。若当前渠道要求更小附件，先查看该渠道实际限制，保留本地母版，再选择合适的H.264编码参数。压缩不改变画面内容或时轴，但可能影响小字与暗部，必须重新核对。CRF、码率和大小按本片内容选择，不把一次CRF21经验写成通用质量保证。

外部发送只在用户当次明确要求时进行，接收位置和授权不从历史交付复用。提交请求、上传文件和消息发送成功是不同状态；取得平台发送结果才报告成功，失败或未知先查已有回执，避免重复消息。发送记录留在本机build/review，公开源码不保存聊天ID、消息ID或个人配置。没有外发要求时只交付本地MP4。

## 认识与故事的编辑验收

选题先在brief.md完成“看前直觉、看后认识、下次可用的问题或情境、机制证据、适用边界”，再设计故事与动画。正式渲染前回看：开头是否暴露了原有直觉的不足，中段哪条证据推动了理解变化，结尾是否回收同一认识；即使删掉术语标签和最后一句金句，故事是否仍能支撑这个认识。

将结论逐项对应到片中过程与来源，区分已证实的机制、思考启发和未知信息。跨领域例子需另有依据，不能靠相似画面推导普遍道理。未通过时先改内容与分镜；已有制作授权内自主修正，不增加例行审批。这是人工编辑检查，当前CLI不会自动评判，技术检查通过不能替代它。

## 全片视觉重复与动态分镜复核

按[视觉叙事与镜头变化](视觉叙事与镜头变化.md)执行，并使用本期 `visual-review.md` 记录结果；旧主题可以从 `templates/episode/visual-review.md` 复制模板后填写。先做全片镜头缩略图总览，标出每镜场景、主体、景别与构图、动作结果、新增信息和重复理由。既要看相邻镜头，也要看远隔镜头是否反复回到同一屏幕或同一种布局。

精做前用简化图形和占位场景构成完整动态分镜，使用实际时长、完整旁白和音乐，检查转场后的视觉任务、段落节奏和情绪变化。必要的关键音效也进入粗剪。静态拼图、几个局部片段和无声视频不能替代全片音画复核。

基础 `vibe.py` 固定1920×1080、30fps，没有 `animatic` 或低清导出参数。可选本地工具使用 `python -m tools.video_review animatic <slug>` 导出完整混音动态分镜与检查记录，不修改 `production_ready`，详见[本地粗剪与检查](本地粗剪与检查.md)。先简化场景细节，再按同一时间轴审看；播放器须确实播放当前完整混音，并核对字幕、画面和音轨版本一致。只播放原曲的旧播放器不满足配音版复核要求。导出成功不等于全片审片通过，也不自动证明画面好看。

当前新片模板的 `player.html` 已按 `film.json.output` 读取 `soundtrack.wav`，可直接复用：在完成草稿场景、配音与时轴后运行 `python vibe.py mix <slug>`，再运行 `python vibe.py serve <slug>`，在其返回的本地地址播放完整动态分镜。`mix` 与 `serve` 不要求 `production_ready=true`。修改声音后重新 `mix` 并刷新播放器；记录草稿源码与音轨版本，避免浏览器仍播放旧混音。此路径可以审查实时画面，若卡顿影响节奏判断，应如实记录并另行导出草稿，不把卡顿预览当作通过。

全片审查至少覆盖：

- 开场2–3秒是否已有主体、动作与问题；其余镜头有没有继续推进这个问题。
- 生活是否始终被装在手机、电脑或卡片里；场景、主体占位、观察尺度和视觉任务是否随叙事变化。
- 转场后的落点是否展示新事件、关系或证据，还是只换字幕、屏幕图片、颜色和装饰。
- 重复镜头是否为观察过程、可比较的对照或结尾回扣服务；不能为凑变化数量而拆散因果。
- 连续听看时，旁白、音乐和动作是否共同推进；不能用增加快切、粒子或逐句音乐闪避掩盖节奏问题。

由当前会话在分段实现后单独重看全片，从整体视角复核，不能把局部检查相加当成全片结论，也不把自查称为独立第三方审查。问题记录包括具体时间码、观看依据、影响、修改方案与复查结果；没有实际观看或试听的部分明确标为未检查。

先检查实际全片粗剪，再定向精修；正式编码后核对镜头总览、关键因果动作、中心认识和声音。返修复查改变部分及邻接转场，并重新看当前全片总览；未变部分须有相同哈希和此前有效记录才可继承。程序检查继续执行，具体画面与实际观看范围才是创作复核的依据。

记录本次审查对应的分镜、画面、旁白、混音版本及产物路径。修改脚本、镜头、时间轴或声音后，更新受影响记录，并复查前后衔接和全片重复感。镜头数量或主体出现时长只能提示风险，不是审美分数或通过阈值。当前 `check`、`require_review`、布局报告和 `finalize` 都不能证明这一项通过。
