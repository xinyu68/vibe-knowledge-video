# 本地粗剪与检查

由当前会话直接负责创作、看图、复查和交付。`tools.video_review` 是可选的本地命令行工具，复用现有 Canvas、Playwright 和 FFmpeg，生成带完整声音的粗剪、镜头总览和技术检查记录；它不调用其他 Agent，不启动编排服务，也不替创作者判断画面好坏。

## 使用条件

按 README 安装依赖，并确保 `ffmpeg`、`ffprobe` 在当前进程的 PATH 中。下列命令中的 `python` 指本项目虚拟环境的解释器。

本期目录需要已有 `film.json`、`plan.json`、实际场景代码、音乐和配音缓存；配音片先完成 `vibe.py narrate` 及时间对齐。另在 `videos/<slug>/shots.json` 保存完整镜头表。没有镜头表的旧片仍可直接使用 `vibe.py`，无需为了继续制作强制迁移。

镜头表可以是数组，或包含 `shots` 数组的对象。每个镜头需要：

- `id`：唯一标识，仅用字母、数字、下划线和连字符，最长 64 字符。
- `start`、`end`：秒数，从 0 开始无缝覆盖 `plan.duration`，每镜结束晚于开始。
- `scene`、`subject`、`composition`：场景、主体、景别与构图。
- `cause`、`action`、`result`：触发、动作、可见结果。
- `new_information`、`transition`：新增认识和转场落点。
- `repetition_reason`：重复理由；新画面允许空字符串。
- `narration_ids`：对应旁白 cue 的 ID 数组，纯音乐段可以为空数组。

描述字段使用中文。程序仅校验字段和时轴，不会因为填好了文字就认定动画已经实现。

## 常用命令

```shell
python -m tools.video_review validate <slug>
python -m tools.video_review animatic <slug> --jobs 2
```

`animatic` 先混音、核对声音输入，再抽帧、编码全片并封装声音。输出为本期输出目录下的 `animatic/animatic.mp4`，默认是 `build/animatic/animatic.mp4`；同时保存镜头总览、动作抽帧、声音报告和版本记录。保持 1920×1080、30fps，不提供低清参数，不修改 `production_ready`，也不覆盖正式成片。

日常需要单项检查时：

```shell
python -m tools.video_review mix <slug>
python -m tools.video_review audio <slug>
python -m tools.video_review evidence <slug>
```

`mix` 重建混音并绑定当前声音输入；`audio` 检查已有混音及配音时间，不能代替试听；`evidence` 重新生成当前源码的全片抽帧和总览。声音或源码变化后必须重做受影响的输出。

当前会话实际检查内容、造型、动作和全片节奏，修正问题并确认可以正式制作后，才在本期配置中设置 `production_ready=true`。然后可继续使用原有 `vibe.py preview/render/finalize`，或显式运行：

```shell
python -m tools.video_review finalize <slug> --jobs 2
```

该命令依次检查声音、抽帧、正式渲染、封装和提取编码后的画面证据，沿用原有技术检查。最终 MP4 默认仍为 `build/final_video.mp4`。已有有效正式成片需单独提取证据时使用 `final-evidence <slug>`；它要求当前源码、成片和技术验证记录一致。

## 创作判断

由当前会话分别完成关键样段检查、全片粗剪复查和成片复查，在本期 `visual-review.md` 记录具体时间码、可见问题、修改和复查范围。简化材质不能省掉人物比例、手部抓握、接触遮挡和动作结构；先看原尺寸样段，确认后再铺开相同主体的其他镜头。

导出成功、布局通过和音画时长一致仅代表相应技术检查通过。仅看过抽帧、未连续观看或未试听的部分必须如实记录，不能据此声称整片已通过审美或听感检查。
