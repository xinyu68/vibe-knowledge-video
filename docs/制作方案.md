# 当前制作方案：音乐驱动的动态知识叙事

版本 4.1，2026-10-28。适用于面向普通观众的带中文配音知识动画短片，独立定义选题、叙事、画面、音乐与验收方法。选题先明确观众能带走什么认识，再设计故事和动画；沿用连续配音、可追踪主体、状态变化和动作复核。仓库中的具体故事、音乐时码与模型不是所有选题的固定模板。

## 1. 成片的目标

让观众先关心一个正在发生的结果，再理解解释它的原理，最后回到自己的生活。画面承担叙事，不把一段知识文字拆成幻灯片。每期至少能清楚回答：谁遇到了什么问题、发生了什么、为什么、这个理解如何帮助观众。

默认规格：中文 AI 配音，16:9，1920×1080，30fps；一句中文下方配英文斜体翻译；背景音乐从 0 秒开始，片尾保留自然尾奏；约 5–8 处重点音效。最终交付一个含旁白、音乐和音效的 MP4。用户指定无口播时切换。

核心分工：**中文配音负责讲述，音乐负责情绪和大结构，动画负责展示过程，字幕帮助理解。** 先按音乐划定段落、换气和高潮，再安排旁白时间窗，最后对齐关键动作。旁白不改写音乐的节奏，动画也不能只跟字幕换页。

## 2. 先确定认识，再设计锚词、主体和故事

创作的第一步是回答：“看完之后，观众会改变哪个直觉，或者多问自己哪一个问题？”先用一句普通话写出认识目标，核对机制与证据，再选择能让观众亲眼理解它的故事。故事与动画承担论证过程，结尾回收已经建立的认识。

选题必须先写清五项：看前直觉、看后认识、下次可使用的问题或情境、支撑机制与证据、适用边界。记录在brief.md，详细标准见[选题与叙事](选题与叙事.md)。例如讲幸存者偏差，观众带走的问题是“还有哪些没有进入我视野的样本”，而不只记住这个术语。

五项不成立时先改切口、缩小主张或换候选题，再设计分镜与动画。热度、漂亮画面和知名术语不能抵消认识或证据的缺失。无需为这项编辑自查另设用户审批；用户明确只要求现象科普时按其定位创作。认识可以是更准确地理解世界，不必强加人生建议；跨领域应用需另外核对，不能用一个实验包办所有社会问题。

锚词优先 2–4 字，指普通人处境，不是知识术语。它既概括全片，也能在结尾获得新含义。

| 原理 | 锚词方向 | 开头处境 | 结尾理解 |
|---|---|---|---|
| 幸存者偏差 | 缺席 | 看不见失败者的经历 | 把没进入故事的人纳入判断 |
| 沉没成本 | 舍不得 | 付出越多越难离开 | 以未来代价与收益判断下一步 |
| 红皇后效应 | 原地 | 拼命跑仍感觉没前进 | 看清相对变化并重新判断方向 |
| 无事故拥堵 | 无形的墙 | 前面没有障碍，自己却走不了 | 看到向队伍后方传播的慢行区 |

这些是创作起点；具体应用仍需研究原理和条件。不要把所有生活困难都套成同一种效应。

上表的锚词和现象解释不能替代认识目标。现有堵车片主要完成了机制解释；若新稿希望进一步讲“理解整体结果也要看个体间的联系”，必须让这一认识贯穿故事并明确证据边界，不能只在片尾加“涌现”两个字。本次规则更新没有改写或重新渲染该成片。

选一个可识别的具体主体，如飞机、顾客、队伍、车票或一段道路。写出“开头状态 → 机制作用 → 结尾状态”。再写事件链，明确每一步改变什么。全片要能在结尾回答开头的问句。

## 3. 前三秒给主体、动作和悬念

第一帧就看得到主体，前 2–3 秒就能看出它正在遭遇的矛盾。开场不是先读百科定义，也不是静止的书或片名。

例如讲“幸存者偏差”，可以用“受损、动力不平衡的飞机还在努力返航”制造一个结果问题。画面有螺旋桨、烟迹、姿态修正与掠过的跑道灯；字幕把问题引向“最危险的伤口为什么看不见”。讲其他题目时，应找到相应的主体动作与结果。

开头短段可以扩大同一困惑：具体主体 → 生活对照 → 信息缺口 → 高潮前问题。跨个人、自然、社会的例子只在机制相同时使用；不为凑尺度强行拼接。

## 4. 音乐决定情绪与落点

先记录实际音源、哈希、解码时长、明显换气/释放、段落变化和尾奏。音量曲线帮助定位，但音乐结构与试听决定叙事高潮。

默认音源为 `assets/music/千年之后 (氛围版) - 原谅他7次.mp3`：解码 159.250 秒；30fps 渲染 4778 帧，视频 159.266667 秒。首重拍约 17.03–17.04 秒，主揭晓固定零起算第 511 帧，即 17.033333 秒。音源检测记录已随项目保存。

| 相对首高潮 T | 叙事与视觉 |
|---|---|
| T 前约 0.63–0.13 秒 | 次要元素退出，画面收暗 |
| T 前约 3 帧 | 主体静止，留出换气空间 |
| T 当帧 | 关键结果、完整锚词与短冲击同时落下 |
| T 后约 0.6 秒 | 术语中英小字补出 |
| T 后约 3 秒 | 轻微呼吸，给阅读时间，再进入解释 |

示例为 16.4–16.9 秒收暗、17.033333 秒揭晓。这里是“明显收弱”，仍有声音。不能夸称完全静音。首高潮后才安排历史、人物和术语解释；中段最多再一次较小强调。

镜头、字幕和音效以同一事件落点组织。小拍承接局部动作，乐句承接完整事件，段落承接理解和情绪变化。舒缓处让观众读完；强化处增加有意义的动作；不要求每拍切画面。

旁白放在适合听清的乐句内，重要揭晓前后留白。默认音源在 16.4–17.9 秒不安排人声，首高潮后的术语可以等画面出现后再读。示例约 18.08 秒开始读出术语；这是本期安排，新主题可按实际文案调整。收束句结束后留自然尾奏；不为了填满片长持续说话。

先写完整事件与因果，再写适合听的语义段落。一个段落包含相互承接的数句，作为一次TTS请求，让句子共享语气；字幕另外拆成短句，不以字幕条数决定合成次数。配音、字幕与动画必须讲同一件事。合成后按真实音频时长核对窗口；太长先改短文案或调整相邻段落，禁止硬截句尾，不默认依靠加速补救。不要抢先读出尚未发生的关键结果。

普通衔接先从约0.2–0.6秒可听空隙调试，避免每句都空1–2秒；段落转折、需要观察的动作、首高潮和片尾可以有更长留白，并标明叙事理由。可听空隙要根据音频实际发声边界检查，不直接拿两个cue窗口之间的距离代替。保留段内自然停顿，不能为追求紧凑统一删静音。

本次无事故堵车示例采用640汉字、10个语义段落、41条双语字幕，普通段间可听空隙中位数约0.525秒，最后人声在150.85秒结束。这些是该文案与音源的实测结果，不是新片必须达到的数字。它们证明段落配音和短字幕可以分开组织，不代表主观听感或完播率已被验证。

## 5. 深色画面必须有层次和语义对比

参考色：背景 `#080e18`，主体文字 `#f0f3f4`，次级文字 `#a6b4c5`，冷蓝 `#79b9de`，暖金 `#eac27b`，风险橙红 `#f17a61`，观察青色 `#62c9cf`。新题可调整，但同一含义尽量使用同一色。

暗背景中要有明亮主体、细节、层次和留白。营业店亮暖灯、有顾客与蒸汽；已停业店更暗、有明确状态。颜色对比传递经营状态、风险、被观察/未被观察等信息。不能通篇只有灰蓝轮廓，也不能把每个元素都做成霓虹高亮。

纹理、胶片颗粒、雾气和暗角只作轻辅助。主体与字幕比装饰更重要。数字使用等高数字；Canvas 中选用 Lora 的默认 lining figures，网页辅助界面声明 `font-variant-numeric: lining-nums tabular-nums`。

先用开场、中段机制、结尾三个代表画面检查整体造型，再扩展全片。人物只有在故事需要其选择或行为时才出现；知识可以由物件、车辆、关系和环境展示。确需人物时，先统一比例、轮廓、五官简化程度、服装与动作姿态，检查正侧面及小尺寸辨识度，不把临时几何人形直接当成完成设计。

有体积的物件可以通过透视、分面受光、玻璃、轮胎和接触阴影实现，不要求写实3D。重点是同一对象在不同镜头仍能认出，暗处仍有层次，色彩标记跨场景保持一致。新的主题可用手绘或2D，只要达到相同的可读性和动作要求。

## 6. 动画用来演示“发生了什么”

每场先列：触发动作 → 主体反馈 → 可见结果 → 观众理解。再设计运动。

| 层次 | 实际例子 | 作用 |
|---|---|---|
| 主体局部动作 | 螺旋桨、机翼/方向舵、脚步、手臂、门 | 让对象像在行动 |
| 受力与反馈 | 动力下降、烟迹、倾斜、修正方向 | 让原因对应后果 |
| 信息生成 | 扫到伤口才登记、返航才填表 | 解释数据从哪里来 |
| 关系改变 | 框缩小排除记录、框展开看见遗漏 | 把抽象机制演出来 |
| 场景承接 | 飞机飞到基地再转为检视图 | 连接叙事过程 |

路径与朝向要一致；到达和登记要对位；相邻飞机不能挤成一团；部件转速不能在停止后仍偷偷转动。每个动作应有开始、过程和完成状态。

不要把动画数量视为完播率保证。判断每处动作是否增加问题、信息或情绪；没有作用的装饰可删。稳态段允许停顿，观众需要时间理解。

优先连续跟踪同一主体：开场遇到问题，中段进入机制，结尾带着新理解离开。以金色车辆为例，速度下降时轮子放慢、制动灯亮起，停稳应保持到观众能辨认；再次加速后灯光与轮速跟着改变。镜头从直路变为俯视环路时，颜色、方向、相邻关系应能帮助观众找回它。

把重要判断变成可见证据。“主体已经离开，问题仍存在”不能只让主体驶出画面再打一句字幕，要让主体与问题同框，或用连续视线、镜头运动证明两者仍在同一系统。对照实验保持未比较的条件一致，标明改变的变量。

如果采用模拟，先检查最小间距、非负速度、对象数量、轨迹朝向、传播方向及对照趋势，再用画面验证观众是否能看懂。说明简化参数、限幅与时间压缩，不能把动画模型的数值当作原论文结果。模拟正确和叙事清楚是两项独立检查。

## 7. 转场与字幕

优先保留同一个物件、路径、光源或观察框，在其变化中进入下一场。遮罩展开、局部推进、短横向揭示可以帮助实现。连续性不成立时重新设计前后动作，避免依赖长时间叠化。

短遮罩也必须检查遮罩底图与下一场的相机、主体位置是否连续，避免遮罩一消失就突然拉远或跳位。一个动作可以跨越字幕和段落边界持续推进，不必每换字幕便清屏、静止或另起镜头。

早期示例字幕基线为中文 y=930、英文 y=988，底部从 y=845 起有柔和暗色托底；新布局按主体位置调整，标题和主题动作避开字幕区。中文优先不超过18字、每屏一条，下一行英文斜体。无口播可从每句约3–5秒、全片25–30句起草；连续配音版按语义和实测发声独立分屏，不强制套用句数或停留时长。短字幕可更快，但必须能读完；过长优先改写而不是缩字。

字幕是叙事的一部分，不能与上方标题反复说同一句。上方展示动作/结构，下面解释观众此刻需要理解的含义。注意完整中文字符、标点和英文斜体，实际抽帧检查裁切与对比。

## 8. 声音与验收

默认 Edge / 云健（zh-CN-YunjianNeural）中文配音，用户可换声音。按语义段落cue缓存原始音频及合成信息，旧逐句缓存仍兼容；按整轨双声道等效响度统一处理，当前旁白目标约−18 LUFS，具体按实测与试听调整。配置与操作见 [配音流程.md](配音流程.md)。

配乐默认 music_mode=constant，整段固定增益；配音版从约 −18dB 起步，检查最响的音乐和最密的旁白再确定比例。不能每句话压低、停顿立即回升；保留源音乐本来的强弱变化。必要时优先让人声稳定，或使用静态均衡改善重叠频段；确需改变大段落时设计约 2–3 秒的缓慢变化，不能恢复逐句闪避。当前稳定配乐版没有额外段落自动化。无口播版可从音乐 −6dB 起步，固定数值都不代替试听。

轻环境声贯穿，5–8 处短音效对应关键动作。首高潮冲击与结果同帧；最终测真峰值，建议不高于 −1.5dBTP，保留动态。只在旁白整轨做所需处理，不对最终全片盲目套用动态响度处理，再次改变音乐起伏。

制作顺序：认识目标与看前/看后变化 → 核对机制、证据与边界 → 选题成立后设计故事卡和锚词 → 音乐结构 → 带旁白时间窗的分镜 → 旁白和字幕 → 合成并实测配音 → 场景代码与动作对位 → 抽帧和动作序列 → 修正 → 固定配乐混音与渲染 → 成片抽帧、技术检查与试听 → 单文件交付。

抽查开场、高潮、转场、密集画面、每种主体动作和结尾。默认特别检查 16.3、16.8、17.0、17.1、17.5、18.0 秒及第 510、511、512 帧。自动边界检查只检查几何，不能识别所有重叠和可读性问题。技术同步通过只代表封装没有时序偏移，不能替代音画主观判断。

验收时说明实际看过和听过的范围。不能因代码能跑就宣称故事吸引人，也不能承诺播放量。

## 9. 每期可以直接执行的检查顺序

1. 先在故事卡写清看前直觉、看后认识、下次可用的问题、机制证据和边界；成立后再设计开头问题、贯穿主体与事件链。分镜逐段写“哪条证据让观众的理解发生了什么变化”，结尾回收同一认识。
2. 三张风格帧检查造型、色彩、主体和字幕层级，确认主题适合这种表达；已有完整制作授权时自主修正，不增加例行审批。
3. 音乐定大结构，旁白按语义段落合成。实测后安排普通衔接、保护区与尾奏，再对齐短字幕及关键动作。
4. 做开场、解释机制、关键对照、结尾的动作序列，确认起因、过程和结果都能看见。检查对象和相机跨转场的一致性。
5. 抽静帧与连续动作看图，修正后渲染。保持源码签名、预览、分段和成片一致；渲染期间冻结视觉源。
6. 最终编码后再次检查文字、黑场、解码、30fps帧时间戳、音画时长、混音真峰值及封装同步。记录主观试听范围，不将技术指标当成听感结论。
7. 按用户指定渠道交付一个MP4。若需压缩，先查当前附件限制，保留本地母版，压缩后重查关键帧和规格；只有消息回执确认才能说发送成功。

通用规则在本文、AGENTS.md与配音/验收文档中。实现参考见 `videos/phantom-jam/`，其中时间映射、汽车模型、脚本断言和检查点均只属于该主题。新会话必须重新写内容、段落、素材与主题动作。
