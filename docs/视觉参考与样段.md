# 视觉参考与样段

## 当前参考边界

用户已明确反馈近期几期视频质量差，不能把这些试片当作制作素材。保留原文件供历史追溯，不从中建立人物、手部或场景素材库，也不将其当作新片的正面风格参考。当前排除近期本地试片 `checking-habit`、`hedonic-adaptation`、`queue-sunk-cost`、`sunk-cost` 的视觉资产；用户日后明确重新指定的部分，再按指定范围考虑。

较早的仓库示例仍可说明配置、音频缓存和渲染方法，不能仅因它能运行或过去交付过，就宣布造型达到本期标准。规则、工程工具和视觉素材分开评价。

## 本期参考怎么选

先根据题材选主体、场景和动作，再寻找匹配的视觉参考。优先用户本次提供或明确认可的作品；也可研究其他合适参考，记录来源与实际观察，不凭“受欢迎”三个字替代分析。

在本期 `brief.md` 的当前制作记录中写下：

- 来源与具体画面／时码。
- 借鉴什么：例如人物比例、侧脸结构、环境光线、持物关系或转场逻辑。
- 不适用什么：视角不同、物件不同、写实程度不同，哪些需要重新设计。
- 本期样段位置、实际检查结果与未解决问题。

这是本期创作依据，不要求所有参考都由用户逐项审批。选不到合适资产就重新设计关键样段，不拿已否定的旧片填空；不照搬别人的镜头和素材来冒充原创。

## 扩展全片之前检查什么

| 对象 | 需要实际看见 |
|---|---|
| 开场 | 第一帧能认出主体，前几秒有具体异常或行动；不靠标题解释全部吸引力 |
| 通用主体 | 人物、物件、图表和场景的比例、连接、空间关系符合本期表达；有意夸张有清楚依据，数据图形不误导数量关系 |
| 人物 | 头身和四肢比例、轮廓、面部结构与本期画风一致，肘腕位置清楚 |
| 手部与接触 | 拇指与指腹方向、抓握点、遮挡顺序；拿起与松开的过程合理，手臂不随目标任意拉长 |
| 关键机制 | 起因、过程、反馈和结果可追踪；关闭字幕后仍能看出什么发生了变化 |
| 转场 | 前场动作有承接，落点带来新的事件、空间或认识，没有长叠影掩盖跳变 |
| 声画 | 按真实声音检查关键动作、停顿与重拍，区分技术对齐和实际听感 |

选择本期最容易失败的几个样段，先看原尺寸和触发／过程／结果，再看连续动作；样段太差就重做造型或动作，不靠加粒子、移动镜头和延长时长补救。

短样段工具与完整粗剪见[本地粗剪与检查](本地粗剪与检查.md)。样段自查不代替全片审片，也不因导出成功就写“视觉合格”。具体观察和返工继续记到已有 `visual-review.md`；下述 JSON 只保存供工具核对的本轮声明与证据绑定。

## 专项视觉审核与放行

本流程适用于每个新题及旧片返修。先检查代表性主体与关键样段，再扩展同类镜头；全片完成后复核新增主体和发生变化的部分。由当前会话实际看最终画面完成审核，不新增用户逐项审批。人物并非必需，比例标准也不统一套用写实人体。

先看原尺寸完整画面，再放大主体局部，检查触发、过程和结果。仅有缩略图、代码中的关节点或“能认出动作”，不足以证明结构合理。以下任一明显问题应记为需返工：肢体或物件连接来源不明、抓握或承重关系不成立、遮挡造成主体误读、图表比例与所表达关系冲突、关键动作中形体突变。修正后重查该段及相邻转场，问题未解决不扩展同类镜头。

先生成当前源码的预览或样段，再准备未审记录（路径相对本期目录）：

```shell
python vibe.py preview <slug>
python -m tools.visual_review prepare <slug> --evidence build/review/layout_audit.json
```

也可传入样段的 `build/samples/<起始帧>-<结束帧>/review/layout_audit.json`，或在 `--evidence` 后列出多个当前报告。输出为 `<film.json.output>/review/visual-review.json`。实际检查后填写 `reviewer`、`scope`、`contains_people`，并逐项填写 `checks`：

| 项目 | 判断依据 | 可否不适用 |
|---|---|---|
| `proportions_structure` | 主体比例、轮廓、部件连接；图表与场景关系符合表达 | 不可 |
| `pose_contact` | 姿态、支撑、接触和受力关系清楚 | 无相关姿态或接触时可说明理由 |
| `occlusion_layers` | 前后层次、遮挡顺序、轮廓辨识 | 不可 |
| `composition_readability` | 主次、画面占位、文字与主体的可读性 | 不可 |
| `motion_continuity` | 触发、过程、结果连贯，形体与接触不突变 | 无相关动作时可说明理由 |
| `character_anatomy` | 有人物时检查头身、肩肘腕、手部、髋膝足及可见承重 | 仅无人入镜时可说明理由 |

每项含 `status`、`observation` 和 `evidence`。状态为 `unreviewed`（未审）、`needs_revision`（需返工）、`passed`（本轮通过）或 `not_applicable`（不适用）；观察须具体到可见关系，证据引用草稿中登记的本期相对图片路径。不能用“看过了”“没有问题”代替判断，不适用必须说明本片为何没有该项。

```shell
python -m tools.visual_review check <slug>
```

正式整片 `render` 与 `finalize` 会检查记录是否通过、证据是否存在且未被替换、源码是否仍是本轮版本。绑定采用视觉相关版本及证据摘要；报告摘要保留图片、动作序列及视觉版本信息，排除仅因制作状态变化而改变的原渲染签名。预览、短样段和 `animatic` 不受此关口阻断，可继续用于检查和返工。改动源码或证据后重新生成并审核；`prepare --replace` 会备份旧记录，将新记录重置为未审。仅切换 `production_ready` 不使视觉审核失效，但正式渲染仍须与当前配置匹配的预览。

工具不识别人体、不自动看图、不生成审美分数，也不能证明实际连续观看或试听。填写记录不能替代上述检查。旧片继续正式制作时同样要新审，不自动补通过；既有媒体保留。只有专用 `.local/self-test-*` 工程自检可豁免，普通视频的 `test_only=true` 不能跳过审核。
