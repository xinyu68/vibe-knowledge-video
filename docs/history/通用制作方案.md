# Vibe 知识大赏：通用制作方案

版本：1.2  
整理日期：2026-10-23

适用于：以代码绘制动画、无口播、由音乐和双语字幕驱动的知识纪录短片

本目录配套文件：

- `选题与内容叙事方案.md`：先选值得讲的问题，再设计有始有终的故事
- `选题库与故事卡模板.md`：候选题、选题评分、故事卡和首尾闭合检查
- `通用执行提示词.txt`：复制给制作 Agent，填入主题和音乐即可开始
- `分镜与音乐分析模板.md`：锚词、音乐结构、分镜、高潮检查和事实核对模板
- `背景音乐说明.md`：本目录音乐文件、实际时长、第一高潮落点与混音起点

## 一、成片要达到什么效果

让观众先在生活处境里认出自己，再通过故事和画面理解一个原理，最后带着新的理解回到生活

全片围绕四件事建立：

1. **处境**：观众正在经历什么困惑
2. **锚词**：这个困惑可以被哪一个短词钉住
3. **物件**：用什么具体、可识别的东西，把原理演出来
4. **音乐**：在哪儿蓄势、在哪儿揭晓、在哪儿停下来理解

基本情绪曲线：

> 立即代入 → 困惑扩大 → 收紧蓄势 → 第一次高潮 → 故事与解释 → 理解加深 → 回到生活 → 留下余味

这是一条创作主线。段落时长跟随实际音乐，不把所有题目套成相同的固定秒数

## 三、写文案之前：找锚词和具体物件

### 1. 锚词

锚词优先为 2～4 个字，代表原理落在普通人生活里的处境、困惑或反直觉瞬间。字数是简洁性目标，不为了凑字数牺牲含义

判断它是否成立：

- 观众一看就能代入
- 能串起全片的主要例子
- 开头和结尾使用同一个词，结尾的理解更深
- 能与一个具体物件或可见动作建立联系

| 原理 | 可选锚词 | 开头的含义 | 结尾的重新理解 |
|---|---|---|---|
| 红皇后效应 | 原地 | 拼命跑，仍在原地 | 理解相对竞争，也重新判断方向 |
| 沉没成本 | 舍不得 | 已经投入太多，无法离开 | 把已经付出的与下一步选择分开 |
| 幸存者偏差 | 缺席 | 没有出现在故事里的样本 | 主动寻找被筛选掉的部分 |
| 最优停止问题 | 再等等 | 总担心下一个更好 | 在明确条件下理解等待与选择 |

这些是创意方向，不替代原理的事实核对和适用条件

### 2. 具体物件

每条片子选一个贯穿物件，再选少量辅助道具

例如：一份名册、一张车票、一条路、一只鸟、一颗种子、一部手机、一架飞机

遮住字幕后，观众仍应认得出它是什么。不能把所有东西都画成光点、连线、圆圈或无意义卡片

为主角物件写出三种状态：

> 开头的状态 → 原理发生时的变化 → 结尾回场时改变的那一处

锚词与物件都确定后，才开始写正式文案

## 四、先分析音乐，再安排段落

输出一张音乐结构表，至少包括：

| 时间范围 | 音乐变化 | 能量与情绪 | 叙事任务 | 画面落点 | 依据 |
|---|---|---|---|---|---|
| 实测填写 | 节奏进入、换气、重拍、编曲展开、回落、尾奏等 | 低／中／高及情绪描述 | 钩子、揭晓、解释、反思等 | 某个动作完成或构图改变 | 波形、能量分析、实际试听 |

必须找到：

- 音频起点与有效结束点
- 第一次明显的“换气＋释放”
- 后续显著的编曲或能量变化
- 适合解释的平稳段与适合反思的安静段
- 最后的尾奏和自然收束位置

音频分析可以辅助找点，不能把短时音量最高的位置自动等同于叙事高潮。需结合实际试听和编曲结构判断

节奏分三层：

| 层级 | 适合承接的画面 |
|---|---|
| 小节拍 | 落笔、物件落定、局部高亮等小动作 |
| 乐句 | 景别变化、一个完整动作、场景交接 |
| 音乐段落 | 揭晓、反转、情绪回落、生活回扣 |

不是每一拍都换画面。字幕读得完、动作看得清，优先于机械卡点

## 五、开头与第一次高潮

### 1. 开头 0～3 秒

第一帧就有与主题有关的具体物件和正在发生的动作，不从黑场慢慢等待

第一句优先采用第二人称，写观众的悖论：

> 你已经……，为什么还……？

这是推荐句式，不是每条片都必须套用的字模。也可以用一个简单选择或可立即参与的小实验，让观众先在心里作答

开场要完成：看得见的东西、正在发生的矛盾、值得继续看的问题

### 2. 开头 3～16.4 秒

通过 3～4 个简洁场景扩大同一种困惑，每场约 3 秒。允许个人、自然、群体等尺度变化，但必须共享同一种机制

若跨领域举例会混淆原理，就用同一场景的近景、全景和后果展开，不能为满足格式拼凑不成立的类比

在高潮前用一句收束或一个发问，把场景归到锚词上。引语和数字只有核实后才使用；没有可靠引语，直接用原创问题

### 3. 第一次高潮：声音、画面、意义同时落下

高潮不仅是出现大字。重拍落下时，画面必须完成一次有意义的变化：显露被遮住的部分、扩大观察范围、揭开矛盾或让选择的后果被看见

动作提前开始，关键结果落在重拍上，落下后留出理解时间

本目录默认音源按 T＝17.033333 秒规划。下面是制作时间表，音画听感仍由带音乐的样片确认。帧号从 0 开始：

| 时间 | 帧号 | 画面与声音 |
|---|---:|---|
| 16.433 秒 | 493 | 开始收暗，次要元素退场 |
| 16.833 秒 | 505 | 接近完成收暗，视觉线索保持简洁 |
| 16.933～17.033 秒 | 508～510 | 静止 3 帧，不用额外声音填满收弱段 |
| 17.033 秒 | 511 | 画面揭晓、锚词出现、低沉冲击音同步 |
| 17.133 秒 | 514 | 墨痕或纸面光晕继续单次扩散 |
| 17.533 秒 | 526 | 扩散逐渐停稳，锚词保持可读 |
| 17.633 秒 | 529 | 术语中文与英文小字出现 |
| 18.033 秒 | 541 | 保持构图，给观众阅读和消化 |
| 约 20.033 秒 | 601 附近 | 随音乐进入具体故事 |

技术要求：

- 锚词实际排版宽度约为画宽的三分之一，根据字数调整字号和字距
- 爆发方式与画风一致，纸面风格用墨晕、纸面提亮或线条展开
- 不用弹跳、过冲、旋转、花字或持续震屏表达冲击
- 已确认的音画落点误差不超过 2 帧；30fps 时为约 66.7 毫秒
- 抽帧能确认视觉时刻，仍需试听带声音的短片确认音画关系
- 换音乐后，以新实测时间 T 替换 17.033333 秒；所有准备和保持动作相对 T 安排
- 中段允许再使用一次较小的爆点，全片最多两次

## 六、全片叙事结构

以下是约 159 秒的初始框架，本目录音源在 159.250 秒结束；中后段时间必须随实际音乐调整：

| 段落 | 初始时间 | 内容 | 观众的变化 |
|---|---|---|---|
| 代入 | 0～3 秒 | 一个生活困惑或选择 | 这和我有关 |
| 扩大 | 3～12 秒 | 同一矛盾的几种表现 | 原来到处都有 |
| 蓄势 | 12～16.4 秒 | 收束到锚词 | 我想知道为什么 |
| 首次高潮 | 16.4～20 秒 | 视觉揭晓与锚词落下 | 原来漏看了这一点 |
| 具体故事 | 20～55 秒 | 人物、事件、实验或最小实例 | 我看到了证据 |
| 演示机制 | 55～95 秒 | 实际展示比较、筛选、累积等过程 | 我理解了因果 |
| 理解加深 | 95～120 秒 | 边界、反例或另一面 | 我知道何时成立 |
| 回到生活 | 120～145 秒 | 开头物件回场 | 我能重新看待自己的处境 |
| 自然收束 | 145 秒～音乐结束 | 锚词回声、一个可带走的问题 | 理解、释然或行动方向 |

历史和术语在开场之后进入。人名、年份只是证据，不把生平介绍当成叙事推进

第一次高潮让观众认出问题，后面的故事解释原因。不要在 17 秒堆完全部答案，也不要为了悬念拖延本应解释的关键信息

## 七、分镜与画面动作

一句字幕对应一个主要变化。画面完成的事情，要能用一个具体动词说出来：筛掉、翻开、落下、连接、遮住、显露、累积、分开

优先使用以下画法：

- 让观众亲自试一次
- 照着句子画，让动词发生
- 用一个最小例子把机制跑完
- 在相同条件下并排比较
- 把已经出现的物件放到同一张关系图中
- 在命名、提问、结论处停住，只留下文字或已有物件

问句、定义、结论不必硬配新图。没有字幕的时间里，画面可以继续完成一个过程

每条分镜都要写清：观众此刻比上一镜多明白了什么。如果只是换了装饰，重写这一镜

## 八、转场规则

先为全片设计一条转场路线，再写动画代码

每个转场明确记录：

> 上一镜留下什么 → 它怎样变化 → 下一镜从哪里出现

| 接法 | 做法 |
|---|---|
| 同一个物件 | 物件保持身份，通过位置、尺度或状态变化进入下一场 |
| 形状接续 | 上一镜的圆、边框、印记等，变成下一场的具体物件 |
| 动作接续 | 上一镜的移动方向、速度或落笔动作，延续到下一镜 |
| 镜头推进 | 推进到一个真实细节，细节铺满后展开为下一场 |
| 镜头拉远 | 原来的局部变成全局的一部分，显露此前遗漏的信息 |
| 开头回场 | 回到同一场景，只改变与结论有关的一处 |

普通转场从 0.5～1 秒试起，按音乐、景别和内容调整；两个复杂画面交叠原则上不超过 0.5 秒

避免：默认每幕淡入淡出、用白闪掩盖所有换场、每句字幕都换构图、让前后两个画面长时间叠着读不清

## 九、画风、构图与动效

### 1. 视觉基调

- 底色：羊皮纸或米白宣纸，纹理克制
- 配色：低饱和暖色，墨灰为主体，赭色或暖金作少量强调
- 质感：纸张纤维、轻微胶片颗粒、柔和暗角
- 实物：有体积、材质、投影，遮住标签仍能识别
- 颜色：每种颜色全片承担相同含义，不能随意交换

具体画风可根据主题改动，先写清一套视觉规则，再贯穿全片

### 2. 构图与安全区域

以 1920×1080 为基准：

- 左右安全边距至少约 96px，上下至少约 54px
- 主体通常放在纵向 12%～76% 区域
- 底部约 80%～95% 区域留给中英字幕
- 同一时刻只有一个主要视觉中心
- 标注避开主体和字幕，必要时用细引线
- 文字不得越出纸张、卡片或画面的可读范围
- 缩到手机横屏大小复查，不能只在大显示器上判断

### 3. 动效

- 使用舒缓的镜头推进、平移和必要的景别变化
- 元素的显露与实际动作配合音乐，不机械地整屏呼吸
- 动作落定后允许停住，让观众阅读
- 不把慢节奏做成全片静止，也不把卡点做成密集快切
- 默认禁止弹跳、旋转花字、过冲回弹、持续震屏
- 纸张、粒子和暗角等环境层不得争夺叙事注意力

### 4. 数字与字体

- 数字使用等高数字：`font-variant-numeric: lining-nums`
- 会跳动的计数器叠加 `tabular-nums`，减少宽度变化
- 数字必须实际计算或有事实来源；模拟数字需标明“示意”
- 字体加载成功后才能抽帧或渲染，防止预览和成片排版不同

## 十、字幕写作

- 中文字幕一句一行，原则上不超过 18 字
- 下方一行英文斜体，忠实且自然，不逐字硬译
- 英文过长时优先同步精简文案，不依靠无限缩小字号
- 每句停留 3～5 秒，根据阅读量与音乐适度调整
- 一句只有一个主要意思，不堆术语、定语和引文
- 可以使用破折号制造停顿，但不能把每句话都写成金句
- 诗意不能替代准确性；描述因果时写清具体发生了什么
- 亮背景使用深色字，暗背景使用浅色字，必要时加柔和托底或阴影

1080p 初始字号可从中文 48～58px、英文 30～36px 试起，以实际字体、行宽和手机观看效果为准

约 159 秒可先规划 25～30 句。以 28 句、平均 4 秒计算，字幕占约 112 秒，剩余约 47 秒用于画面演示、转场、高潮保持与尾奏。时长变化后重新核算，不能机械固定句数

## 十一、声音

- 必须使用选定的背景音乐，从第 0 秒开始
- 保留原曲的蓄势、换气和自然尾奏，不用底噪或冲击音填满所有空隙
- 音乐音量克制，保留动态；不靠整体变响制造高潮
- 本目录原文件测得约 −10.55 LUFS，可先将音乐降低约 6 dB（线性增益约 0.50），再混入少量音效。此值是混音起点，最终成片另测真峰值和试听，不覆盖原文件
- 环境底音可以不用；使用时极轻，不遮盖音乐细节
- 全片约 5～8 处关键音效：第一高潮、少量重要转场、关键理解和片尾
- 音效需要与实际动作有关，避免每条字幕都有提示音
- 冲击音在约定的落点触发，音乐与音效一起试听，检查有没有掩蔽或削波
- 最终播放不能只确认“有音轨”，必须核对实际听感、首尾和关键卡点

## 十二、代码实现约定

优先复用已有可用的渲染工具。Canvas、SVG、Remotion、HyperFrames 都可以，工具选择不能代替分镜设计

建议：

- 全片由统一时间轴驱动；同一时间的画面应可复现
- 音乐落点、字幕起止、场景边界和音效登记集中管理
- 所有随机过程固定种子，避免每次渲染结果不同
- 用帧号定义关键事件，用秒数维护一般分镜
- 需要模拟时预计算并按时间回放，避免跨帧状态导致跳帧后结果错误
- 音频和视频使用同一主时间线，不为每段重新起音乐
- 转场由前后场景共同设计，不能靠渲染后临时叠一层淡出补救
- 输出前检查字体、颜色空间、总帧数和音画时长

30fps 下，关键视觉事件采用 `frame = round(T × 30)`。本目录默认 T＝17.033333 秒，对应从 0 开始计数的第 511 帧。声音按同一个 T 安排，再核对最终编码文件。若其他音源实测恰好是 17.0 秒，才使用第 510 帧

## 十三、制作顺序

### 阶段 A：方案

1. 核对输入与可用音乐文件
2. 任何文案之前，确定观众处境、锚词、具体物件和结尾变化
3. 分析音乐，形成时间结构表
4. 核对原理与事实，列出可靠来源及适用条件
5. 写中英字幕与完整分镜，逐镜写清转场、音乐落点和观众得到的信息

### 阶段 B：样片

6. 先制作带真实音乐的 0～22 秒样片，覆盖钩子、蓄势和第一高潮
7. 抽关键帧、看转场拼图，并实际播放带声音的片段
8. 修正主体可识别性、阅读节奏、高潮落点、文字遮挡和转场衔接

### 阶段 C：全片

9. 延用通过样片验证的视觉规则和时间线，扩展全片
10. 各场景检查入场、中段、退场及交接帧
11. 完整实时观看并试听，修改影响理解和听感的问题
12. 编码导出并检查最终文件

默认先展示方案和样片供审阅。只有用户明确要求逐阶段确认时，才把确认作为停止点；用户已授权直接制作时，可以在按标准自查后继续，不自行添加反复审批流程

## 十四、验收标准

### 内容与叙事

- [ ] 前 3 秒能看见具体物件、动作和困惑
- [ ] 开场与观众有关，没有术语或历史铺垫
- [ ] 每一幕比上一幕增加了信息
- [ ] 第一高潮前有期待，落点处有视觉与认知变化
- [ ] 遮住字幕，仍能看出核心动作
- [ ] 例子能支持原理，类比没有混淆机制
- [ ] 结尾回到开头，并重新理解锚词

### 音乐与节奏

- [ ] 实测并试听了实际音乐文件
- [ ] 全片段落跟随音乐结构，而非平均切段
- [ ] 动作提前起，关键结果在落点完成
- [ ] 第一高潮音画偏差不超过 2 帧
- [ ] 有回落、阅读时间和纯画面段落
- [ ] 音效克制，音乐换气处没有被填满
- [ ] 尾奏自然收束，没有突然截断

### 画面与字幕

- [ ] 无文字重叠、越界、溢出纸面或明显对比度问题
- [ ] 中英文行都能读完，英文没有被挤成小字
- [ ] 图形不进入字幕区，标签不压住关键细节
- [ ] 关键实物可识别，不是任意装饰图
- [ ] 转场短而清楚，前后场景不长时间混叠
- [ ] 数字使用等高字形，计数器位置稳定
- [ ] 已检查高潮前后指定帧与连续音画片段

### 技术与文件

- [ ] MP4，1920×1080，30fps，视频和音频编码可正常播放
- [ ] 字体全部加载，没有缺字或替代字体排版变化
- [ ] 同一时间重复渲染画面一致
- [ ] 视频时长与音乐有效长度匹配，尾部没有意外黑场
- [ ] 音画同步、无削波、无解码错误
- [ ] 已完整实时观看并试听最终文件，而非只看静帧
- [ ] 未完成的检查如实说明，不把抽帧检查称为完整观看

## 十五、事实、来源与交付

制作方案中保留事实表：

> 出现时间｜年份／人名／数字／引文｜片中表达｜来源｜适用条件或不确定性｜是否核实

优先使用论文、原著、机构档案、官方资料等原始来源。无法核实的引文不要使用，不编造名人说法。模型、数量或画面比例为演示设计时，在画面中简短标明

最终文件建议使用正式片名，例如 `片名.mp4`。不要把临时英文文件名或版本串当作发布片名

最终文件只交付一个含音乐与音效的 MP4；聊天中提供片名、规格和事实核对清单。源码、分镜与中间文件留在工程目录，用户要求时再提供。没有用户授权，不自动发布或上传

## 十六、对前一版制作方式的修正

- 用“第一帧发生一件事”替代等待中的缓慢入场
- 用观众处境或选择开场，避免先介绍画面里的物件
- 用同一物件的连续变化推动叙事，避免静态图加字幕轮播
- 用音乐结构确定段落，避免做好画面后再补背景音
- 用认知揭晓承接第一重拍，避免只有片名和闪光
- 先把 0～22 秒做对，再扩展片长
- 把完整实时观看和试听列为交付检查，不能仅凭技术导出成功判断完成

## 十八、内容生产的前置步骤（v1.1 新增）

正式写分镜前，先按《选题与内容叙事方案.md》完成选题和故事卡。阅读顺序建议：选题与内容叙事方案 → 选题库与故事卡模板 → 本制作方案 → 分镜与音乐分析模板

前置产出：

1. 观众在什么具体处境中，为什么会关心这个问题
2. 标题的期待、开头主问题、结尾答案三句，检查是否一致
3. 支持答案的事实或可复算演示，以及不能推出的结论
4. 锚词和贯穿物件，从开头到结尾怎样变化
5. 主问题在哪提出、在哪回答，中段怎样逐步提供证据

内容闭合是进入正式制作的条件。五项检查为：问题闭合、因果闭合、物件闭合、期待闭合、情绪闭合

第一个重拍要交付一次真实进展，后面继续解释机制。结尾应明确回应开头，不能只出锚词、引用名言或问一句“你怎么看”

制作与发布后的内容复盘方法、资料来源和适用边界见《选题与内容叙事方案.md》。选题评分和时间建议都是编辑工具，不是平台算法或效果保证
