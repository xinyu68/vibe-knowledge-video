# 中文配音制作流程

本流程适用于其他主题。当前默认带中文旁白，声音为 Edge / 云健（zh-CN-YunjianNeural），用户可换声音或指定无口播。默认合成直接使用项目内 Edge 接口，无需外部 ttsCN 脚本和 API key；旧的外部脚本参数继续兼容。首次环境准备见[新电脑启动](新电脑启动.md)。完整方案以“配音讲述、音乐控制大结构、动画展示过程”为分工，不要求了解示例故事或历史会话。

## 文案与时间轴

先完成故事与事实核对，按音乐划出叙事段落，再写适合听的连续讲述。一个语义段落讲清一件事，可以包含几个有关联的短句；默认整段合成，让句子有前后语境。不要把每条字幕独立送入TTS，否则容易句句重新起腔。保留原意和不确定性，不把示意模型讲成史实。

每个合成段落记录 `id`、`text`、`start`、`end`，并另行维护与字幕的对应关系。`cues` 表示合成和放置的单位，可以是一段，不限定为一句；`end` 是最晚结束时间，不是要求拖长到此时。一个段落对应多条字幕，中文可精炼，英文按同一意思翻译。字幕换行或换屏不应自动造成旁白停顿。画面已经显示的术语可以直接读出，无须再加一层重复文字。

音乐控制段落、高潮与尾奏；在大段落内部根据实测人声安排事件和字幕。只在因果转折、给观众观察结果或音乐换气等明确需要处留长停顿；普通衔接不机械空出1–2秒。开头直接提出问题，结尾回答开头后停声，让尾奏自然收束。重要重拍前后用 `protected_gaps` 留白，不为追求连贯而填满全片。

不要把试听文件作为正文直接循环：试听文件只用于确定音色，正式旁白必须用本期文案重新生成。

## 合成、缓存与实测

1. 用 `vibe.py new <slug> --title <片名> --topic <主题> --narrated` 创建本期目录；会设置 `film.json.narration`、固定配乐起始增益和空白 `narration.json`。填本期正文，不能保留空 `cues`；`output` 可指定本期 `build-voiceover` 等目录保留历史版本。
2. 完成 `python bootstrap.py` 后，直接用 `python vibe.py narrate <slug>` 生成。每个 `cue` 作为完整段落合成；并发最多两个请求。Edge 合成联网，无需 key，原生词边界会保存到缓存元数据。旧环境可选 `--tts-cli <外部脚本路径>`，该路径只用于当次运行。默认 `rate: "+0%"`，不要靠提高语速修补过多文案。
3. 原始语音与元数据放在本期 `audio/narration/<id>/`。文本、声音、语速相同可复用，音频 SHA256 防止缓存被悄悄替换；不缓存本机技能路径。修改一句涉及段落语气时，重合成包含它的整个段落；不必重新生成未变的段落。
4. 工具根据实际波形裁掉首尾空白并保留80ms / 150ms余量，内部自然停顿保留。新骨架 `max_tempo: 1.0`，自然时长超窗就报错；优先删减重复表达、重写整段，或在音乐结构允许的范围内调整窗口和动作。禁止硬切句尾，不用加速掩盖节奏问题。旧配置最多1.10倍的能力仍兼容，但不是当前默认制作方案。首次合成后若在入窗阶段失败，已生成的缓存仍可用于测量，调整窗口后可复用。
5. 输出目录由 `film.json.output` 决定，默认 `build/`；其中 `narration-timing.json` 记录每段实际结束、裁剪量、加速倍率、音频哈希、保护区和响度。`mix` 会校验并重建整轨，已有缓存不再次联网。再根据边界映射字幕与动作，见下文；`narrate` 本身不自动生成或对齐 `plan.json` 字幕。

时间轴的最小例子（只是格式，必须替换成本期真实文案与完整窗口）：

```json
{
  "backend": "edge",
  "voice": "zh-CN-YunjianNeural",
  "rate": "+0%",
  "target_lufs": -18,
  "music_mode": "constant",
  "max_tempo": 1.0,
  "protected_gaps": [[16.4, 17.9]],
  "cues": [
    {"id": "P01", "start": 0.25, "end": 8.0, "text": "本期的开场问题。接着描述一个能看见的矛盾，让后一句承接前一句。"}
  ]
}
```

`start` 是音频片段入点，`end` 是最晚结束时间，真实结束记录在输出报告的 `actual_end` 中。示例窗口不保证能容纳示例文字，必须合成后实测。旧示例的 `subtitle` 是从1开始的字幕编号；多字幕段落也可以用 `subtitle` / `subtitle_end` 记起止编号，但这些只是创作映射记录，混音工具不会据此切分、移动或校验字幕。实际显示仍以 `plan.json.subtitles` 为准。换音乐后重新设置 `protected_gaps`，不套用示例时码。无口播请求移除 `film.json` 的 `narration` 字段即可；保留正文文件方便以后恢复。

## 混音

旁白整轨按最终双声道播放的等效响度测量，再使用两遍 loudnorm 统一处理，默认目标 −18 LUFS、真峰值上限 −2dBTP；当前工具由 loudnorm 动态控制整轨响度与峰值，不把每条字幕或每段语音单独压成同一响度。原始和处理后的实测数据均写入报告。

当前默认 `music_mode: "constant"`：整段音乐使用 `film.json.music_gain_db` 的固定增益，不根据旁白句子的开始、停顿和结束改变音量。当前示例设为 −18dB；保留音乐源文件本来的强弱、换气和尾奏。旁白统一响度、环境音和短音效单独处理，最终全轨检查真峰值，必要时整体线性衰减，不能用削波掩盖问题。

选择配乐音量时，先看旁白最密集及音乐最响的段落。句间短空档保持同一音乐增益，不在每次停顿抬高。先调整人声和稳定配乐的比例；必要时再对人声做轻压缩或对配乐做静态均衡，不盲目增加自动闪避。仅在明确的叙事大段落需要时设计缓慢变化，仍不能逐句回升。

旧版逐句闪避保留为显式可选 `music_mode: "duck"`，只用于复现历史处理。用户已经反馈 14dB 闪避和快速恢复造成忽大忽小，因此不能作为当前默认。保护区只用于保证高潮前后无旁白，在 constant 模式下不额外改变音乐增益。

## 验收

- 所有段落在指定窗口内且不相互重叠，默认实测 `tempo` 约等于1；保护区间的旁白采样必须为零。
- 复核段内自然连读与段间空档，普通衔接不重复长停顿；有意的留白单独标注原因，不能只看平均语速。
- 旁白的句意与当前字幕、场景一致；关键动作出现前不抢先揭晓结果，必要时延后一句。
- 原有重拍帧、画面动画与音乐自然尾奏保持对位。
- 正式渲染前看抽帧，渲染后全片解码、核对音画时长、AAC 封装延迟和真峰值。
- 波形与响度检验不能判断所有错读和语气问题。主观试听了哪些区间就记录哪些，不得把程序检查写成“已听完整片”。

本期字幕和分镜保存在 `plan.json` / `storyboard.md`；旁白的精确口语化文本以 `narration.json` 为准。`videos/missing-planes` 保留早期逐句合成示例，当前段落合成与独立字幕的实现参考 `videos/phantom-jam`。

## 把段落语音映射到字幕和动画

先把全文按语义分段，再为每段写独立的字幕切分表：原旁白片段、精炼中文、英文翻译。可参考 `videos/phantom-jam/subtitle-script.json`；其中每段的原旁白片段连接后覆盖整段正文，不能漏句，也不能拿精炼后的字幕直接匹配完整口语音轨。

TTS若返回原生词边界，会存入 `audio/narration/<id>/source.json` 的 `word_boundaries`，含 `text`、`offset_sec`、`duration_sec`。先核对词边界拼接文本与实际旁白一致，再换算到影片时间：在未变速时，影片时间约等于段落 `start + offset_sec - trimmed_lead`。字幕可提前少量出现、在下一条开始前结束，以阅读和句意为准；拆到单个汉字的插值只是近似，不是精确的音素识别。

通用工具仅保存这些元数据，不负责自动字幕对齐。边界缺失、文本不匹配或改词后，不能猜一个平均字速充当精确结果：应重新取得匹配的边界，或逐段标注并实际核对。字幕的停留时间、字号和英文行宽仍需单独检查；不强行凑成固定条数，也不为了维持固定3–5秒而破坏连续讲述。

动作也绑定语义：讲到“停下”时观众应看见停稳；讲到“仍然存在”时，要让已变化的主体与仍在的结果同时可见。先确定段落窗口，再按关键词或语义句的时间安排动作起点、过程和结果保持。音乐的关键落点保持固定，普通解释镜头可随实测旁白调整，不能让全片按字幕编号机械换镜头。

`videos/phantom-jam/timing_build.py` 展示了完整文本匹配、字幕映射、段落排时和故事时间映射。它包含本片专属段落编号、镜头节点和时限，只能作为实现参考；新主题应按自己的音乐、文案和场景改写本期对齐脚本，不能直接执行它来处理别的主题。修改字幕后由项目工具同步 `plan.js`，不要手工维护第二套文本。

## 节奏的测量与回看

测量“说完到下一段说起”的可听空档，而不只减两个配置窗口。源文件自带的首尾静音、保留余量和剪辑间隔都会影响听感。保存采用的能量阈值及窗口；阈值测量仅辅助排查，不能可靠区分所有轻声字、呼吸和静音。普通连贯衔接可以先按约0.2–0.6秒可听空档调试，再结合语义、音色和实听调整；结论、悬念及音乐高潮允许更长留白，并在分镜写清目的。

本次幽灵堵车示例使用10个语义段落、41条字幕，普通段间可听空档中位数约0.525秒，人声结束后保留约8.4秒尾奏。以上来自本片 `audio/timing-audit.json` 的测量，是实例，不是新片必须满足的数量或时长。该记录明确未进行全片主观试听；不能据此宣称所有起腔、错读和情绪问题都已通过听感验证。

交付前记录实际试听过的片段，重点听开场、连续解释段、段与段的接缝、音乐最强处及结尾。若感觉慢，先检查重复信息、句句收尾、无任务的空镜和停顿；若感觉赶，先简化文字并给结果留可见时间。改善来自语义和事件的连续性，不等同于不断增加字数、加速或取消呼吸。
