# 中文配音制作流程

本流程适用于其他主题。当前默认带中文旁白，声音为 Edge / 云健（zh-CN-YunjianNeural），用户可换声音或指定无口播。合成使用 ttsCN CLI，项目不保存个人机器的技能路径，也不需要 API key。完整方案以“配音讲述、音乐控制大结构、动画展示过程”为分工，不要求了解示例故事或历史会话。

## 文案与时间轴

先完成故事与事实核对，再将字幕改成适合听的完整短句。保留原意和不确定性，不把示意模型讲成史实。旁白可以比字幕略口语化，但二者应逐句对应；画面已经显示的术语可以直接读出，无须另外叠字幕。

每句记录 `id`、`text`、`start`、`end` 和对应字幕编号。`end` 是最晚结束时间，不是要求拖长到此时。句子读完后保留音乐和动作的呼吸。重要重拍前后用 `protected_gaps` 留白。开头直接提出问题，结尾回答开头后停声，让尾奏自然收束。

不要把试听文件作为正文直接循环：试听文件只用于确定音色，正式旁白必须用本期文案重新生成。

## 合成、缓存与实测

1. 用 `vibe.py new <slug> --title <片名> --topic <主题> --narrated` 创建本期目录；会设置 `film.json.narration`、固定配乐起始增益和空白 `narration.json`。填本期正文，不能保留空 `cues`；`output` 可指定本期 `build-voiceover` 等目录保留历史版本。
2. 在项目虚拟环境安装 `requirements-tts.txt`，准备 ttsCN CLI；用 `vibe.py narrate <slug> --tts-cli <本机 scripts/tts.py 路径>` 生成。每个完整句子单独合成；同一句内部保持自然连读。并发最多两个请求，各自独立临时目录。Edge 合成联网，无需 key；脚本路径只由当次参数传入。
3. 原始语音与元数据放在本期 `audio/narration/<id>/`。文本、声音、语速相同可复用，音频 SHA256 防止缓存被悄悄替换；不缓存本机技能路径。
4. 根据实际波形裁掉首尾空白并保留 80ms / 150ms 余量。仅在略超窗口时保音高加速，最多 1.10 倍；仍超长就改写或重新合成，禁止硬切句尾。若窗口显著短于自然表达，应调整文案或分镜，不盲目加速。
5. `build-voiceover/narration-timing.json` 记录每句实际结束、裁剪量、加速倍率、音频哈希、保护区和响度。`mix` 会校验并重建整轨，已有缓存不再次联网。

时间轴的最小例子（只是格式，必须替换成本期真实文案与完整窗口）：

```json
{
  "backend": "edge",
  "voice": "zh-CN-YunjianNeural",
  "rate": "+0%",
  "target_lufs": -18,
  "music_mode": "constant",
  "max_tempo": 1.1,
  "protected_gaps": [[16.4, 17.9]],
  "cues": [
    {"id": "01", "start": 0.25, "end": 3.9, "subtitle": 1, "text": "本期的开场问题。"}
  ]
}
```

`subtitle` 是 plan.json 中对应字幕的从 1 开始的编号；读出画面已有术语时可为 null。`start` 是音频片段入点，`end` 是最晚结束时间，真实结束记录在输出报告的 actual_end 中。换音乐后重新设置 protected_gaps，不套用示例时码。无口播请求移除 film.json 的 narration 字段即可；保留正文文件方便以后恢复。

## 混音

旁白整轨按最终双声道播放的等效响度测量，再使用两遍 loudnorm 统一处理，目标 −18 LUFS、真峰值上限 −2dBTP；仅在峰值需要时动态限制，避免逐句强行压成同一响度。原始和处理后的实测数据均写入报告。

当前默认 `music_mode: "constant"`：整段音乐使用 `film.json.music_gain_db` 的固定增益，不根据旁白句子的开始、停顿和结束改变音量。当前示例设为 −18dB；保留音乐源文件本来的强弱、换气和尾奏。旁白统一响度、环境音和短音效单独处理，最终全轨检查真峰值，必要时整体线性衰减，不能用削波掩盖问题。

选择配乐音量时，先看旁白最密集及音乐最响的段落。句间短空档保持同一音乐增益，不在每次停顿抬高。先调整人声和稳定配乐的比例；必要时再对人声做轻压缩或对配乐做静态均衡，不盲目增加自动闪避。仅在明确的叙事大段落需要时设计缓慢变化，仍不能逐句回升。

旧版逐句闪避保留为显式可选 `music_mode: "duck"`，只用于复现历史处理。用户已经反馈 14dB 闪避和快速恢复造成忽大忽小，因此不能作为当前默认。保护区只用于保证高潮前后无旁白，在 constant 模式下不额外改变音乐增益。

## 验收

- 所有句子在指定窗口内且不相互重叠；保护区间的旁白采样必须为零。
- 旁白的句意与当前字幕、场景一致；关键动作出现前不抢先揭晓结果，必要时延后一句。
- 原有重拍帧、画面动画与音乐自然尾奏保持对位。
- 正式渲染前看抽帧，渲染后全片解码、核对音画时长、AAC 封装延迟和真峰值。
- 波形与响度检验不能判断所有错读和语气问题。主观试听了哪些区间就记录哪些，不得把程序检查写成“已听完整片”。

当前示例的字幕和分镜仍在 `storyboard.md`；旁白的精确口语化文本以 `narration.json` 为准。中文保留精炼字幕，英语与其对应；首高潮后一句对应画面上的“幸存者偏差”。
