# n8n 知识视频制作流程

这条流程把现有完整片目的配音、固定音量混音、短片预览、人工审片和全片渲染接到 n8n。选题、资料、剧本、美术与动画仍在视频工程中创作，第一版不声称能从一句话自动写动画。

## 文件

- `VibeVideo.node.js`：独立的本机桥接节点，注册类型 `CUSTOM.vibeVideo`。仅调用固定 HTTP API，不执行任意命令
- `workflow.json`：可导入工作流，ID `vibeKnowledgeVideo001`，名称“知识视频 · 配音预览与审片返修”
- `generate-workflow.cjs`：生成工作流的源文件。修改流程后运行 `node integrations/n8n/generate-workflow.cjs`
- `VibeVideo.test.cjs`：隔离契约测试，运行 `node --test integrations/n8n/VibeVideo.test.cjs`

完整安装和运行说明见 [本地 n8n 工作流](../../docs/n8n工作流.md)。节点复制到现有 n8n 的 custom-nodes 后需要重启 n8n 才会加载，已有其他节点和工作流应保留。

## 操作方式

1. 在“本期参数”填写已有片目目录名，默认 `phantom-jam`。桥接默认 `http://127.0.0.1:5681`，短片默认 0–12 秒，单次最多 30 秒
2. 从编辑器选择“手动开始”执行，每个制作节点等待自身后端任务结束，画布实时高亮当前阶段。接口触发的执行在运行中主要显示状态，等待审片或完成后再查看节点轨迹
3. 点击节点查看输出的 Binary 标签：配音节点提供预览区间配音；预览节点提供画面、短片、混音。JSON 的 `artifacts.player` 可看全片实时播放器
4. 到“人工审片”时打开上一节点输出的 `review_url`，或 Wait 节点的等待链接。表单显示短片、完整播放器链接、版本和所有配音段落 ID
5. 选择通过、返修或取消。通过才开始全片渲染；返修建立新版后重新配音和预览；取消保留已生成版本
6. “查看最终成片”的 `artifacts.final_video` 打开完整 MP4。完整母版不复制到 n8n 数据库

## 审片返修

配音返修同时填写准确段落 ID 和替换后的完整段落；不要把连续叙述拆成逐句 TTS。字幕单独填 JSON 数组，例如 `[{"index":0,"zh":"新的字幕","en":"New caption"}]`，索引从 0 开始。修改配音不会自动改字幕、画面或字幕时间。仅填写意见会保留意见和制作新版，不会自动代写动画。

本流程默认最多返修两轮。分镜、主体、视觉重复、知识结论等结构修改，需要回到片目源文件修改后重新发起制作。技术检查不能代替完整观看和事实核对。

审核节点从当前轮预览的执行记录取制作 ID/版本，与表单隐藏值比较；桥接再次检查版本。三版分别使用独立的原生 Wait 固定路径 `review-r1`、`review-r2`、`review-r3`。旧版本链接在恢复执行前就被拒绝，不会占用新版本的审核等待。审核请求有幂等键，避免返修已写入而响应中断后重复建立版本。

## 本机 API 测试入口

发布工作流后可以 POST 到 n8n 的 `/webhook/vibe-knowledge-video`，请求体可含 `source_slug`、`preview_start`、`preview_end`。接口只控制这些制作参数，不能跳过人工审核或指定任意命令。服务保持绑定本机，不通过公网隧道暴露。

## 停止与重试

配音或渲染时点击 n8n Stop，节点会向桥接发送任务取消。普通失败显示在具体节点，日志末尾随错误返回。同一执行、节点、制作 ID 和版本使用同一幂等键；重新开始完整执行会建立新的制作版本。机器/进程强制退出不能发送取消，桥接恢复时负责标记中断任务。

小型媒体附件每项最多 24 MiB；超限或取回失败时在 `media_warnings` 说明原因并保留本地链接。全片文件始终仅保留链接。

## 验证范围

工作流参数根据已安装 n8n 2.44.7 的 Wait 1.1 / Switch 3.2 实现核对；Wait 原生表单支持图片、视频和链接。单测覆盖本机 URL 约束、旧表单拒绝、明确字幕修改、审核重试幂等、媒体类型、停止取消和审核必经路径。真实环境已验证导入、配音和字幕返修、重启保留审片等待、全片渲染及手动停止，详见 [接入验收记录](../../docs/n8n接入验收.md)。
