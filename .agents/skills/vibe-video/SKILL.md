# 知识视频制作

项目根目录是本文件上三级的目录，含 `AGENTS.md`、`vibe.py` 与 `videos/`。在该目录运行命令，使用项目虚拟环境。由当前会话持续负责创作判断和交付，不启动制作团队或编排服务。

## 首次环境准备

新电脑或环境缺失时，按[新电脑启动](../../../docs/新电脑启动.md)运行 `python bootstrap.py`，检查本次十秒自检的结果。已有可用环境无需每期重装；新配音直接用 `python vibe.py narrate <slug>`。普通 `doctor` 只检查本地依赖，不能宣称语音网络通过。工程自检使用专用测试图形，不进入创作素材库。

## 确定本次范围

- 只讨论：研究题材与方案，停在讨论结果；不创建整片制作任务。
- 新片：按下面阶段推进。新骨架使用 `python vibe.py new <slug> --title "片名" --topic "主题" --narrated`；具体参数以 `new --help` 为准，无口播时省去 `--narrated`。
- 续做或返修：先读 `videos/<slug>/brief.md` 的“当前制作记录”和最新 `visual-review.md`，确认用户最新要求替换了哪项旧决定；只重做受影响内容及其衔接。
- 工程或规范维护不触发制作流程。没有用户重新开始的指令，不继续暂停中的影片。

## 维护少量、有效的记录

使用已有 `brief.md` 的“当前制作记录”，不另建平行的状态系统。记当前目标、已确定的取舍、特例、尚未解决的问题和最新有效输出；详细文案、时轴与审片结果链接到原文件。阶段切换、收到重要反馈、暂停和恢复时更新，不逐次记录工具调用。

一次改动先判断影响：改变认识会影响故事与分镜；改旁白会影响音频、字幕和动作；改动作会影响转场和样段。沿这个范围更新并重新验证，别让旧输出继续冒充当前版本。

## 按阶段工作

仅打开当前阶段需要的规范。下列条件是创作者自查条件，不是让用户逐项审批，也不能只填表就宣布通过。

| 阶段 | 读取 | 完成依据 |
|---|---|---|
| 认识与故事 | [选题与叙事](../../../docs/选题与叙事.md) | 普通人可复述的认识、可核查证据与边界；开头疑问有片中过程回答，结尾回扣 |
| 文案与声音结构 | [制作方案](../../../docs/制作方案.md)、[配音流程](../../../docs/配音流程.md) | 测定音乐节点；完整语义段旁白的实测时长与保护区；字幕独立分屏；配乐稳定 |
| 镜头与关键样段 | [视觉叙事](../../../docs/视觉叙事与镜头变化.md)、[视觉参考与样段](../../../docs/视觉参考与样段.md) | 原尺寸、局部与过程帧完成专项视觉审核；主体结构和接触问题已返工复查，才扩展同类镜头 |
| 完整混音粗剪 | [本地粗剪与检查](../../../docs/本地粗剪与检查.md) | 实际时长、完整声音和全片画面共同检查；重复、长空档、动作与讲述错位有具体时码和修改结果 |
| 精做与交付 | [渲染与验收](../../../docs/渲染与验收.md) | 返修后重查受影响段落与全片衔接；最终编码文件的技术检查及实际审片范围明确 |

剧本、声音和镜头允许小步回改，不要求一次写完锁死。先验证高风险动作，再扩展同类镜头；不要到整片渲染后才首次看人物或手。

## 视觉先试再铺开

先选本期适用的视觉参考并记录借鉴范围。用户已否定的近期试片不能抽取为素材，也不能作为造型或动画质量标杆；不要用“代码可复用”替代视觉判断。没有适用素材时重新设计本期样段；不强制人物入镜，不把某套画风套到所有题目。实际引入的本期素材需加入 `film.json.sources`。

人物不能只以“风格简化”为理由省掉比例、肘腕、抓握和遮挡。抓住、松开、接触时至少看触发、过程、结果；实际样段以故事需要为准，不机械规定镜头数量。每个新镜头应增加事件、关系或证据；为了对照、解释或回扣而复现时记录理由。

所有题材均按[专项视觉审核](../../../docs/视觉参考与样段.md#专项视觉审核与放行)检查实际画面；人物、物件、图表和场景按其可见结构判断，不以“动作可辨”代替“结构合理”。由当前会话记录具体观察、证据与返工结果。准备审核命令只生成未审草稿；正式整片渲染和合成要求当前版本的记录通过，单改 `production_ready` 不足以放行。通用项目不能跳过，人物专项仅在无人入镜时说明不适用。

早期短样段使用 `python -m tools.video_review sample <slug> --start 0 --end 4`；时间按本期动作选择。它沿用全片时间轴和当前混音，不要求完整镜头表或 `production_ready=true`。已经有配音配置但缺少所需缓存时，先合成本期旁白；不要删除配音配置来伪装已检查声音。

完整粗剪使用 `python -m tools.video_review animatic <slug>`，需要真实 `shots.json` 覆盖全片。抽帧、短样段和三张风格图不能替代全片节奏检查。技术参数及输出路径见工具文档，不在此重复。

## 诚实审片与收束

在本期 `visual-review.md` 写明时码、现象、原因、修改及复查证据，区分原尺寸抽帧、动作序列、连续观看、主观试听和机器检查。只能报告实际完成的检查；生成了视频、看到了波形或字幕，不等于听过整片。无法试听时记录限制，提供带声音样段，不把问题勾为通过。

用户已授权的常规返修自主完成。局部修改复用未变化的配音缓存和有效渲染分段，素材或源码变化后重建相关证据。交付时指出成片位置、实际检查及仍存在的限制；旧片的通过记录不能给新片背书。
